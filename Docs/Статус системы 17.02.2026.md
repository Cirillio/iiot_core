# Отчет о текущем состоянии и функционале IIoT системы
**Дата:** 17 февраля 2026 г.
**Статус:** v3.5 (Стабильный)

## 1. База данных (PostgreSQL + TimescaleDB)
Центральное хранилище, оптимизированное для временных рядов.

*   **Гипертаблицы:** Таблица `metrics` преобразована в гипертаблицу с партиционированием по времени.
*   **Реактивность:** Реализован механизм `LISTEN/NOTIFY`. При каждой вставке триггер `trg_notify_metric` отправляет JSON-пакет в канал `metrics_realtime`.
*   **Конфигурация:** 
    *   Внедрена таблица `system_config` с глобальными настройками (Deadband, интервалы).
    *   Исправлены ошибки типизации (`DOUBLE PRECISION`) и опечатки в алиасах полей.
    *   Реализована очистка данных (Seed) с `RESTART IDENTITY` для предсказуемости ID.
*   **Текущие сенсоры (Seed):**
    1. `ID 1`: Boiler Temperature (Port 7, Analog, 0-120°C).
    2. `ID 2`: System Pressure (Port 6, Analog, 0-16 Bar).
    3. `ID 3`: Main Pump Status (Port 0, Digital, ВКЛ/ВЫКЛ).

## 2. Сборщик данных (IIoT.Collector)
Высокопроизводительный сервис на .NET 10.

*   **Драйвер:** Modbus TCP (NModbus). Опрашивает ADAM-6017 (эмулятор).
*   **Connection Pooling:** Реализован в `DeviceService`, предотвращает постоянные переподключения.
*   **Фильтрация (Deadband):**
    *   **ANALOG:** Записывает значение, только если изменение превышает порог (`DeadbandThreshold`).
    *   **DIGITAL:** Записывает значение только при смене состояния (0 -> 1 или 1 -> 0).
    *   **Force Update:** Принудительная запись раз в 10 минут (`DataHeartbeatSec`), если данные статичны.
*   **Логирование:** 
    *   Уровень `Information` для ключевых событий.
    *   Уровень `Debug` для фиксации прохождения фильтров.
    *   Уровень `Trace` для сырых значений портов (минимизация шума в консоли).
*   **Надежность:** При падении БД данные уходят в локальный SQLite буфер (`buffer.db`) и автоматически выгружаются при восстановлении связи.

## 3. Web API Gateway
Связующее звено между БД и клиентами.

*   **MetricsObserver:** Фоновый сервис, который слушает канал Postgres и мгновенно пересылает данные в SignalR.
*   **SignalR Hub:** Транслирует телеметрию всем подключенным веб-клиентам в формате JSON.
*   **Dapper:** Используется для всех операций с БД, настроены кастомные `TypeHandler` для Enum и JSONB.

## 4. Мониторинг (React Hub Listener)
Веб-интерфейс для оператора (React + Vite + Tailwind).

*   **Дизайн:** Современный полноэкранный минимализм (стиль Apple/Industrial). Убраны лишние тени, обводки и визуальный шум.
*   **Локализация:** Полностью на русском языке.
*   **Функционал:**
    *   **Dashboard:** Автоматическое определение типа данных. Для цифровых датчиков отображаются статусы **ВКЛ/ВЫКЛ**, для аналоговых — динамические графики (Sparklines).
    *   **Журнал событий:** Прокручиваемая таблица с закрепленным заголовком и точностью времени до миллисекунд.
    *   **Deduplication:** Логика на уровне хука `useMetrics` предотвращает появление дубликатов в таблице из-за React StrictMode.

## 5. Симулятор (Python)
Эмулятор промышленного модуля ADAM-6017.

*   **Генерация:** 
    *   `Port 7`: Sin(x) масштабированный.
    *   `Port 6`: Cos(x) масштабированный.
    *   `Port 0`: Меандр (мигалка 0/1).
*   **Протокол:** Modbus TCP на порту 5020.

---
**Итог:** Система полностью синхронизирована. Конфигурация портов в БД совпадает с выдачей симулятора. Коллектор эффективно фильтрует данные, а UI отображает их без задержек и дубликатов.
